# Project structure

The App Router stays in `app/`: each route keeps its `page.tsx`, and route-specific loading and error boundaries live beside it. This preserves public URLs while keeping Next.js conventions visible.

| Directory                                                                                                                                            | Purpose                                                                                                   |
| ---------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `app/`                                                                                                                                               | Routes, root layout, global tokens and styles, metadata, loading and error boundaries.                    |
| `components/ui/`                                                                                                                                     | Reusable controls and Radix-based primitives.                                                             |
| `components/layout/`                                                                                                                                 | Navigation, footer, theme controls and shared page shell.                                                 |
| `components/feedback/`                                                                                                                               | Reusable error, empty-state and route-recovery UI.                                                        |
| `components/product/`, `components/cart/`, `components/account/`, `components/auth/`, `components/blog/`, `components/contact/`, `components/about/` | Feature-specific views, providers and interactions.                                                       |
| `components/api-resources/`                                                                                                                          | Resource-specific Fake Store API demonstration views.                                                     |
| `components/sections/`                                                                                                                               | Home page sections.                                                                                       |
| `data/`                                                                                                                                              | Static editorial content, including the single FAQ source.                                                |
| `lib/`                                                                                                                                               | Product schema and pure browser-state, catalog, pricing and order helpers.                                |
| `lib/i18n/`                                                                                                                                          | Locale cookie helpers and Persian interface phrase dictionaries.                                          |
| `services/`                                                                                                                                          | External Fake Store API requests and error normalization. Product requests belong in `productService.ts`. |
| `hooks/`                                                                                                                                             | Reusable application hooks.                                                                               |
| `tests/`                                                                                                                                             | Pure logic and browser flow checks.                                                                       |
| `public/`                                                                                                                                            | Static images and product concept imagery.                                                                |
| `docs/`                                                                                                                                              | Architecture, feature inventory and project decisions.                                                    |

The structure review removed duplicate legacy product and mobile-hook files. It also removed an unused mixed-content data module and a generated repository snapshot. Keep generated outputs out of source control and add new files to the relevant feature directory. Reuse `lib/product-schema.ts` as the sole product model, including when reading browser storage.

Local Persian journal content lives in `data/blog-posts-fa.ts`; the original English articles remain in `data/blog-posts.ts` and `data/additional-blog-posts.ts`. User-facing phrase dictionaries are grouped by feature under `lib/i18n/phrases/`. External Fake Store API values remain in their source language.

The unused-code audit removed an unmounted statistics section, unused UI primitives and their direct dependencies, a hook used only by those primitives, and unreferenced placeholder images. The product concept sheets remain because the product gallery constructs their URLs from product IDs at runtime.

## Failure and empty states

`app/error.tsx` catches errors beneath the root layout, while route-level `error.tsx` files can provide focused messages. All route errors use `components/feedback/route-error.tsx` and its retry action calls the App Router `reset` function. `app/global-error.tsx` is the last-resort boundary for failures in the root layout; it includes its own document shell. `app/not-found.tsx` handles unknown routes and explicit `notFound()` calls. These boundaries do not replace data-query errors: queries show `components/feedback/status-panel.tsx` with a retry action, while genuinely missing records use its empty state. Keep loading states alongside routes or within data views as appropriate.
